MES 3 - Backend .NET + SQL Server en serio

Objetivo
Sentirte comodo leyendo, modificando y defendiendo un backend mas serio, donde la logica importante ya no vive solo en Angular sino tambien en ASP.NET Core, SQL Server y los stored procedures que controlan autenticacion, permisos y operaciones por sistema.

Que use realmente en este proyecto

Backend (.NET)
- ASP.NET Core Web API en .NET 8.
- JWT para autenticacion.
- TokenService para emitir tokens con claims.
- ADO.NET para ejecutar stored procedures.
- Controlador de autenticacion con login y logout.
- Controlador generico de entidades por prefijo de sistema.
- Lectura de headers personalizados como Sistema y X-Session-Id.
- Envio dinamico de parametros de seguridad a SQL si el stored procedure los soporta.
- BCrypt para validacion y hash de contraseñas.
- Swagger y CORS para desarrollo.

Frontend (Angular)
- Angular 20.
- Componentes standalone.
- Angular Router con lazy loading por modulo.
- Guards de autenticacion y permisos.
- Interceptors para auth, loading y errores.
- Estado simple con BehaviorSubject en stores.
- Shell dinamico con menu segun el sistema actual.
- Formularios reactivos.
- Angular Material para UI.
- Persistencia de token, sesion y sistema seleccionado en localStorage.

Base de datos (SQL Server)
- Base central con tablas ADM, PAT y AUTH.
- Stored procedures por convencion de prefijos.
- Login por sistema con procedimientos separados.
- Auditoria de sesiones y accesos.
- Perfiles, roles y asignaciones por sistema.
- Categorias y proveedores dentro del modulo Patrimonio.

Importante
Este proyecto no siguio exactamente el plan original del mes 3.
No terminaste armando un backend con DTOs, EF Core avanzado, paginacion real ni dashboard de metricas.
Lo que hiciste fue otra cosa, y bastante valiosa: construiste una base backend mucho mas cercana a un sistema empresarial, con autenticacion multi-sistema, permisos, auditoria de sesiones, stored procedures con contexto de seguridad y una estructura preparada para crecer por modulos.

Proyecto 3
Sistema de Inventario y Patrimonio

Objetivo del proyecto
Demostrar que sabes trabajar con un backend mas serio y con una base SQL mas rica, donde la aplicacion no es un CRUD aislado sino una solucion modular con autenticacion, control de permisos, sesiones auditadas y logica de negocio delegada a stored procedures por sistema.

Descripcion del proyecto
Sistema de Gestion de Inventario y Patrimonio es una aplicacion modular compuesta por un frontend Angular y una API en ASP.NET Core. El acceso se realiza desde un login comun que permite entrar a distintos sistemas, como Administrador y Patrimonio. El backend identifica el sistema actual mediante un prefijo, ejecuta el stored procedure correspondiente y propaga informacion de seguridad como sesion, IP y User-Agent para que SQL Server pueda validar permisos y auditar acciones.

Que construiste realmente en este proyecto
- Login multi-sistema.
- Seleccion de sistema antes de iniciar sesion.
- JWT con claims de perfil y sistema.
- Logout con cierre de sesion en base.
- Propagacion de sesion autenticada desde frontend a backend.
- Auditoria de accesos y operaciones en tablas AUTH.
- Administracion de sistemas, usuarios, perfiles y roles.
- Asignacion de perfiles a usuarios.
- Modulo Patrimonio con categorias y proveedores.
- Menus y rutas dinamicas por sistema.
- Validacion de permisos tanto en Angular como en SQL.

Convencion real del backend
- Login por sistema: {PREFIJO}_Login
- Consulta de entidad: {PREFIJO}_{Entidad}_S
- Alta o actualizacion: {PREFIJO}_{Entidad}_IU
- Cierre de sesion: AUTH_CerrarSesion_IU
- Parametros de seguridad opcionales: @uiSesion, @ip, @userAgent

Que hace cada parte
- AuthController resuelve login por sistema, genera JWT y registra/cierra sesiones.
- EntidadController arma el nombre del stored procedure segun el sistema y la entidad.
- AccesoDatos ejecuta SPs y detecta si soportan parametros opcionales de seguridad.
- TokenService emite el token con claims de usuario, perfil y sistema.

Flujo real de autenticacion
1. El usuario selecciona un sistema en la pantalla de login.
2. Angular envia credenciales a POST /api/Auth/login con el header Sistema.
3. El backend ejecuta el procedimiento de login correspondiente, por ejemplo ADM_Login o PAT_Login.
4. Si el login es correcto, el backend genera el JWT y registra una sesion en AUTH.
5. Angular guarda token, usuario, sesion y sistema actual en localStorage.
6. Los interceptors propagan Authorization, Sistema y X-Session-Id en las peticiones.
7. Al hacer logout, Angular llama a POST /api/Auth/logout y SQL cierra la sesion.

Seguridad real implementada
- JWT para autenticacion.
- Guard de autenticacion para rutas protegidas.
- Guard de permisos por roles requeridos en cada ruta.
- PermissionService para resolver roles desde distintas estructuras del usuario.
- Interceptor que agrega token, prefijo del sistema y session id.
- Backend que reenvia sesion, IP y User-Agent a SQL cuando corresponde.
- Validacion de contraseñas con BCrypt.
- Auditoria de login, logout y operaciones administrativas.
